本规范定义 Agentic 产品的职责分层与接口边界。产品通过确定性的领域操作维护真实状态，通过 Agent 组合操作完成开放任务。规范适用于知识库、任务管理、工作记录等产品，不指定传输协议、数据库、模型或运行环境。

## 职责模型

| 组成 | 输入与输出 | 责任 | 不承担 |
|---|---|---|---|
| 领域能力 | 操作参数 → 领域结果 | 数据语义、身份授权、事务、版本、幂等、审计 | 文风、任务编排、Agent 提示 |
| 访问适配 | CLI / HTTP / gRPC 请求 → 同一领域操作 | 协议解析、身份传递、结果编码 | 独立业务规则、旁路写入 |
| MCP | 工具参数 → 领域结果及工具说明 | Agent 可发现的方法、参数语义、前后置条件、错误恢复说明 | 写作策略、隐式生成或改写 |
| Skill | 用户目标、材料与偏好 → 任务产物 | 研究与工作方法、默认写作模板、质量检查 | 赋予权限、保证数据库约束 |
| 呈现 | 持久内容与格式版本 → 可阅读界面 | 排版、公式、图表、交互与失败回退 | 擅自改动源内容 |
| Plugin | 可安装包 → skills / hooks / adapters / resources | 分发、依赖声明、版本兼容 | 新的领域层或权限来源 |

MCP 是面向 Agent 的访问适配。它既不要求领域能力通过 HTTP 绕行，也不要求与底层函数一一对应。明确、无隐含任务判断的批量读取可组合成一个工具。面向复杂目标的多步骤任务由 Skill 或任务执行层编排。

## 不变式

- **INV-1 领域独立性**：没有 LLM、MCP 或已安装 skill 时，领域操作仍可执行。
- **INV-2 入口等价性**：相同身份、有效权限、参数和基线状态经不同入口执行，具有相同领域语义。接口可以暴露不同子集，不能提供不同约束。
- **INV-3 约束集中**：权限、并发、数据合法性和事务由领域能力执行；提示词与 hook 不能成为唯一保障。
- **INV-4 任务方法独立**：改变写作偏好或任务方法，不要求修改基础服务或 MCP 契约。
- **INV-5 模板与 schema 分离**：写作模板是可调整的组织建议；schema 只强制实际领域行为依赖的数据结构。可程序检查不等于应该强制。
- **INV-6 显式效果**：调用描述、请求与回执明确操作对象、副作用和结果；普通保存不隐式生成、补写或重新组织内容。
- **INV-7 并发与重试**：修改绑定基线版本；重试绑定同一操作身份和候选。冲突不能静默覆盖，同一身份不能用于不同候选。
- **INV-8 持久结果**：连接中断不等于操作失败；异步任务可查询最终状态。排队、持久化、发布完成不能混报。
- **INV-9 呈现独立性**：渲染失败不改变源数据；扩展语法具有正式格式契约，不能仅由某个 skill 私下约定。
- **INV-10 Agent 同权约束**：内置 Agent 与外部调用者遵守同一领域约束。长期职责是明确授权，不是绕过写门的理由。
- **INV-11 可归因**：系统记录操作身份、版本与结果；模型声称的身份和检查通过不替代系统记录。
- **INV-12 独立分发**：Plugin 的依赖与兼容范围明确；安装不隐含授权，缺少可选 skill 不影响领域接口可用性。

## 领域操作契约

每个操作须定义输入、输出、对象范围、权限要求、前后置条件、副作用、失败语义。原子粒度按业务完整性确定；多个字段共同构成一次改动时允许一次提交。原子能力不等于细碎的存储指令。

```typescript
interface OperationRequest<T> {
  requestId: string;       // 有持久副作用时需要
  expectedRevision?: string; // 修改已有对象时需要，或等价的并发控制
  input: T;
}
type OperationResult<T> =
  | {ok: true; data: T; revision?: string}
  | {ok: false; error: {code: string; message: string; details?: unknown}};
```

具体产品可以使用不同字段名或事务模型，但必须保留这些语义。身份来自可信调用上下文，不能由普通业务参数自报。异步操作返回可恢复的操作标识及状态，另有结果查询接口。回执须区别已接受、执行中、已提交但未完成交付、完成与失败。

Step 1：验证调用身份和请求形状。
Step 2：核对授权对象、版本和幂等候选。
Step 3：验证领域不变量并原子提交。
Step 4：记录并返回可恢复的结果。

此步骤定义对外保证，不要求所有产品采用相同内部实现。数据库事务、文件锁或版本控制均属于具体产品设计。

## MCP 契约

工具描述说明：何时使用、参数来源、修改范围、成功结果、错误含义与恢复方式。MCP 允许分页、字段选择、结果结构适配，不允许把调用失败包装成成功或扩大授权。运行时工具名以实际发现的 schema 为准，skill 不假设固定客户端前缀。

## Skill 与偏好

Skill 定义适用任务、输入、方法、输出、完成标准及异常处理。通用方法、用户长期偏好与本次要求分开；本次明确要求覆盖默认偏好。偏好组合不能突破授权范围。写作模板、示例及长篇指南作为按需读取的资源随 plugin 分发。

软性质量检查可以返回建议或促使 Agent 修改，不应直接阻断合法数据保存。证据真实性和论证质量不能由章节正则、字数或模型自报证明。

## 呈现与扩展

内容格式定义源码、版本、渲染行为、资源能力和不支持时的回退。执行内容与产品身份权限隔离。辅助图像不能成为文章语义的唯一载体，静态或不可执行阅读器仍应获得文字解释。派生缓存必须绑定源版本，不能成为另一个可独立编辑的事实来源。

## 演进

现有实现不构成本规范的前提。产品采用规范时需要明确兼容契约、迁移边界和实际实现状态。既有数据不得因替换写作方法而被自动改写。暂存兼容入口须说明其语义，不继续传播已移出的写作规则。
