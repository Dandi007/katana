# 自包含性检查清单

> 这份清单是可读性 review 的"机器可检测"部分。
> 作者在派 subagent 冷读前、subagent 返回结果后、修复完毕后，都可以用这份清单做静态检查。
> 能用 grep / ripgrep 检查的条目都给了命令。

## 静态检查（不需要理解文档内容）

### 1. 未解释的内部编号

典型出现形式：`F17`、`§08`、`Q-UI-6`、`bg_a4860899`、`ses_1e364f288ffe`、`MR !2`、`FI-264`、`feature/#123`。

命令：
```bash
# 内部 findings / golden-order 编号
grep -nE "F1[0-9]|§0[0-9]|Q-[A-Z]+-[0-9]" <docs>

# 后台任务 / session ID（OpenCode 体系）
grep -nE "bg_[a-f0-9]{6,}|ses_[a-z0-9]{10,}" <docs>

# GitLab MR / Issue 编号
grep -nE "MR !\d+|#\d+|FI-\d+" <docs>
```

如果命中，必须二选一：
- 就地用一句话解释（比如 `F17 "冷重启 vs 状态机分层"`）
- 改写成**内容描述**（比如"本文档采用的设计哲学"），彻底去掉编号

### 2. 未解释的人名

命令：
```bash
# 常见中文姓名 + 常见英文昵称
grep -nE "（[张王李刘陈杨黄周吴][一-龥]{1,2}）|[a-z]{4,10}（[a-z ]+ 作者）" <docs>
```

（grep 这条精度有限，主要靠 subagent 冷读发现。）

修复方向：
- 改写成**角色**（"原 pmj/finchdata Flask GUI 作者"、"后端负责人"）
- 或就地补一句"<姓名>：<什么角色 / 负责什么>"

### 3. 未解释的历史引用

典型：`用户原话`、`2026-05-10 讲过`、`上次 session`、`checkpoint 说`、`之前我们聊过`、`前两天那个讨论`。

命令：
```bash
grep -nE "用户原话|用户在 20[0-9]{2}-[0-9]{2}-[0-9]{2}|之前(讨论|聊过|我们)|上次 session|checkpoint|ses_[a-z0-9]+" <docs>
```

修复：历史引用本身不能对读者证明任何事。改写成**本文采纳的产品约束**："本文采纳的产品约束：端侧程序必须暴露 HTTP + WebSocket 控制 API"。

### 4. 未落地的跨引用

典型：`见 xxx.md §X`、`承接 yyy 报告`、`沿用 zzz §N 风险清单`。

这些**不一定是错**，但要检查：

- 被引用的文件是不是和本文一起发？
  - 一起发 → 可以用
  - 不一起发 → 必须**就地内联结论**
- 引用的章节号是否存在？（章节重编后容易失效）
- 引用文件的子章节是否还在？（文件被重写可能移位）

命令：
```bash
# 找所有跨引用
grep -nE "见(同目录)?\s*[\`'\"]?[^\`'\"]+\.md|承接 [^，。]+ 报告|沿用 [^，。]+ §" <docs>
```

### 5. 未定义的术语（高频词）

典型高风险未定义术语：
- 项目代号：`G01`、`4090`、`Orin`、`dagger`、`finchdata`、`trunk`、`ksyun`、`drb`
- 技术缩写：`SSE`、`MJPEG`、`RBAC`、`ADR`、`RTSP`、`WebRTC`、`APE`、`RBC`、`LDS`、`VLA`、`MLOps`
- 业务术语：`task`、`prompt`、`episode`、`checkpoint`、`intervention`、`ESTOP`、`task_request`
- 优先级 / 分期：`P0`、`P1`、`P2`、`Phase A`、`Phase B`、`Phase C`
- 角色：`操作员`、`遥操员`、`supervisor`、`oncall`

对每篇文档，应该有一个"术语与前置约定"节（或类似）。自查：
- 文档前 30% 出现的术语，是否都在术语节里有一句话解释？
- 非全球通用的缩写（`SSE` 对 JS 程序员常识，但对 PM 不是）是否标注？
- 业务编号（`task_type 9009`）是否说明"UI 应显示业务名，数字编号是内部分类码"？

### 6. 内部 URL / IP

典型：`http://172.22.62.133:9000/...`、`http://10.x.x.x`、`https://agirobot.feishu.cn/wiki/XXX`。

如果文档会发给**外部**读者（评审方、合作方、候选人），内网 URL 读者打不开 → 必须替换或删除。

命令：
```bash
# 私网 IP
grep -nE "https?://(172\.(1[6-9]|2[0-9]|3[01])|10\.|192\.168\.)\.?[0-9]+" <docs>
# 内部域名
grep -nE "https?://[^ ]*\.(feishu|lark|agirobot|内网域名)\.(cn|com)" <docs>
```

## 结构检查（需要读文档，但不需要领域知识）

### 7. 文档开头是否有"读者与范围"节？

典型应包含：
- 目标读者
- 本文覆盖 / 不覆盖
- 前置依赖
- 一句话产品摘要 / 当前状态（draft / reviewed / frozen）

### 8. 文档开头是否有术语节？

评估标准：
- 覆盖后文前 30% 出现的所有高频术语
- 定义不是 circular（用没定义的词解释新词）
- 业务术语和实现术语**分别分组**（对不同读者友好度不同）

### 9. 章节编号是否前后一致？

命令：
```bash
# 找所有章节标题
grep -nE "^## [0-9]|^### [0-9]" <docs>
```

检查：
- 编号是否连续（1, 2, 3 ... 不跳号）
- 是否有先用 `§8` 后在 `§10` 才定义（前向引用）

### 10. 表格是否自包含？

每张表的列名应该是自解释的，或在表前解释。

不好的例子：列 "✅ / ❌"，不说明依据。
好的例子：列 "是否在 scope（判断标准：现场单用户 / 低技术门槛 / 需直接控制 G01）"。

## 内容检查（需要领域知识，靠 subagent 冷读）

这部分不能用 grep 自动跑，必须靠 subagent review：

- 字段表格是否有 schema（type / 必填 / 默认 / 示例）？
- endpoint 表格是否有 body 示例 / 错误码 / 幂等语义？
- 事件 catalog 是否有 payload schema / 触发时机？
- 状态转换是否画出？
- 每个 workflow 是否有成功态 + 失败态 + loading 态描述？
- 开放问题是否有 owner + 阻塞关系？

## 自查节奏

| 阶段 | 跑什么检查 |
|---|---|
| **作者写完初稿** | 静态检查 1-6（grep 能跑的）+ 结构检查 7-10 |
| **派 subagent 前** | 同上，先修掉机器能发现的 |
| **subagent 返回后** | 合并 subagent 发现 + 静态检查补漏 |
| **修复完毕后** | 再跑一次全部 + 派一个 subagent 冷读验证 |

## 综合命令（一次跑完所有 grep 检查）

把下面保存为 `scripts/self-check.sh`（TODO）或直接一次运行：

```bash
DOC="$1"
echo "=== 内部编号 ==="
grep -nE "F1[0-9]|§0[0-9]|Q-[A-Z]+-[0-9]|bg_[a-f0-9]{6,}|ses_[a-z0-9]{10,}|MR !\d+|FI-\d+" "$DOC" || echo "  (clean)"
echo ""
echo "=== 历史引用 ==="
grep -nE "用户原话|用户在 20[0-9]{2}-[0-9]{2}-[0-9]{2}|之前(讨论|聊过|我们)|上次 session|checkpoint" "$DOC" || echo "  (clean)"
echo ""
echo "=== 跨引用 ==="
grep -nE "见(同目录)?\s*[\`'\"]?[^\`'\"]+\.md|承接 [^，。]+ 报告" "$DOC" || echo "  (none)"
echo ""
echo "=== 内部 URL ==="
grep -nE "https?://(172\.(1[6-9]|2[0-9]|3[01])|10\.|192\.168\.)\.?[0-9]+" "$DOC" || echo "  (clean)"
```
